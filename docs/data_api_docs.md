# Data and API documentation

The reference for everything the project stores and every command that makes it: BigQuery datasets, dbt models, output files and the command line.

This project has **no web API**. Its interfaces are the BigQuery tables (read by dbt, Tableau exports and reports), the CSV files Tableau reads, the reports, and the command line. This page is generated by `uv run python -m src.build_data_api_docs` from the dbt files, the SQL and the command definitions, and a test fails if it is out of date, so it matches the code.

For the meaning of each measure see the [metric dictionary](metric_dictionary.md); for the raw tables in detail see the [data dictionary](data_dictionary.md); for which data is real and which is synthetic see [synthetic data](synthetic_data.md).

**Contents:** [Conventions](#conventions) · [Datasets](#datasets) · [Run order](#run-order) · [dbt models](#dbt-models) · [Tests](#tests) · [Output files](#output-files) · [Command reference](#command-reference)

## Conventions

| Topic | Rule |
|---|---|
| Data | GA4 events are **real**; CRM customers and orders, ad spend, Segment events and the identity ground truth are **synthetic** (Faker, seed 42). |
| Money | US dollars. `net` revenue is after refunds. ROAS is revenue divided by spend, not profit. |
| Time | UTC. Dates are `DATE`, timestamps are `TIMESTAMP`. The GA4 window is 2020-11-01 to 2021-01-31; "as of" is 2021-02-01. |
| Keys | `customer_id` (CRM), `user_pseudo_id` (GA4 device), `session_key` (device + GA4 session id), `order_id`. |
| Models | The four attribution models are `first_touch`, `last_touch`, `linear`, `time_decay`. `ga4_session` is a fifth view used only as a benchmark in ROI and budget tables. |
| Names | `stg_` staging, `int_` intermediate, `fct_` fact (events or measures), `dim_` dimension (descriptions). Double underscore separates source from entity (`stg_crm__orders`). |
| Privacy | No output file contains a name or email. The ground-truth table is read only by the scoring step, never by a dbt model. |

Columns are in the [data dictionary](data_dictionary.md).

## Run order

Run from the repository root with the virtual environment active and `gcloud auth application-default login` done.

| Step | Command | Reads | Writes |
|---|---|---|---|
| 1 | `uv run python -m src.synthetic.ga4_extract` then `src.synthetic.generate_crm` | optional: the generated CSVs are committed | data/synthetic/ |
| 2 | `uv run python -m src.load_to_bigquery` | raw | `raw.*` |
| 3 | `uv run python -m src.identity.run` | raw | `identity.*` |
| 4 | `uv run dbt run --project-dir dbt --profiles-dir dbt` | raw, identity | `staging`, `intermediate`, `marts` |
| 5 | `uv run dbt test --project-dir dbt --profiles-dir dbt` | every model | pass or fail |
| 6 | `uv run python -m src.identity.accuracy`, `src.attribution_report`, `src.dbt_results --run` | identity, marts, dbt | `reports/`, `docs/dbt_test_results.md` |
| 7 | `uv run python -m src.export_for_tableau` | marts | `tableau/data/*.csv` |

## Tests

Two kinds of dbt test protect the models: the **column tests** above (`unique`, `not_null`, `relationships`, `accepted_values`) and **30 singular tests** in `dbt/tests/`, each a query that returns rows only when something is wrong. The recorded result of the last full run is in [dbt_test_results.md](dbt_test_results.md). Python tests in `tests/` (pytest) run the real model SQL on small hand-built tables.

| Singular test | What it protects |
|---|---|
| `assert_ad_spend_inside_ga4_window` | Ad spend is built from GA4 sessions, so every spend day must fall inside the GA4 window. |
| `assert_app_orders_have_no_transaction_id` | App orders never happen on the website, so they cannot carry a GA4 transaction id. |
| `assert_attribution_checks_all_pass` | Every recorded attribution check passes, and the table really holds the checks (it cannot pass by being empty): 4 models x 6 per-model checks, 2 first/last checks x 2 models, the unknown-source ... |
| `assert_attribution_credits_conserve_orders_and_revenue` | Every order gets exactly one full unit of credit per model, and no revenue is added or lost: the credited revenue of each model equals the net revenue of the orders mart. |
| `assert_attribution_follows_its_rules` | Re-checks first and last touch against the touchpoints themselves, written a second way: known_source the credited session exists in the journey, has a known source, carries the credited channel, and ... |
| `assert_attribution_keys_are_unique` | The attribution tables have composite keys, which column-level unique tests cannot express. |
| `assert_campaign_roi_ties_out` | Campaign ROI must tie to its inputs: all the ad spend is in it under every model, all the campaign-tagged revenue the models credit is in it (none lost because a campaign has no spend row), the GA4 ... |
| `assert_clv_covers_the_buyers_and_ties_to_history` | CLV has one row per buyer, its historical value is the real net revenue, and nothing is negative. |
| `assert_clv_prediction_is_consistent` | The prediction must follow its own recipe: horizons scale together, clv = history + 12-month prediction, and more repeat orders in the same time never lower the expected rate. |
| `assert_cpa_ties_out` | The CPA tables must agree with the ROI tables they are built on, with the order data, and with themselves: same rows, spend, orders and revenue; CPA recomputed from spend and orders; new customers ... |
| `assert_customer_orders_tie_to_orders_mart` | The profile must carry exactly the orders and money of the orders mart: nothing lost, nothing doubled. |
| `assert_customer_profile_is_consistent` | Every CRM customer appears once, and the profile's own columns agree with each other. |
| `assert_customer_sessions_tie_to_sessions_mart` | Sessions on linked devices: the profile must count exactly the identified sessions of the sessions mart. |
| `assert_identify_hash_matches_customer` | Where an identify event carries an email hash, it must equal the hash of the customer it names. |
| `assert_identity_devices_exist_in_ga4` | Every linked device must be a real GA4 device. |
| `assert_matched_orders_have_a_session` | A matched web order must point to a real session, and that session's device, if identity resolution linked it to a customer, must be linked to the SAME customer that placed the order. |
| `assert_order_history_is_consistent` | Each customer's orders are numbered 1, 2, 3... |
| `assert_orders_cover_crm_orders` | No order may be lost, doubled or changed in value on the way to the orders mart. |
| `assert_orders_match_segment_tracks` | Every order has exactly one Segment "Order Completed" event, carrying the same customer, value, channel and status, and there are no such events without an order. |
| `assert_paid_sessions_match_ad_spend` | The synthetic ad spend was sized from real paid sessions: one row per campaign per day, with clicks between 1.00 and 1.15 times the sessions. |
| `assert_refunds_match_status` | A refunded order is refunded in full; a completed order has no refund. |
| `assert_rfm_covers_exactly_the_buyers` | RFM has one row for every buyer and none for customers without orders, and carries their real totals. |
