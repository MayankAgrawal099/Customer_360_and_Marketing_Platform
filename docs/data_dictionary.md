# Data dictionary

Every table in the project's raw layer (BigQuery dataset `raw`), every column, and where it comes from.
The dbt layers (staging and marts) are documented in their own section as they are built.

## How to read this

Each table has a **Source** tag:

| Tag | Meaning |
|---|---|
| **REAL** | Copied unchanged from the public GA4 sample (real, obfuscated Google Merchandise Store data). |
| **SYNTHETIC** | Generated by `src/synthetic/generate_crm.py` (Faker, fixed seed 42) and linked to real GA4 users, dates and purchases. Nothing in it describes a real person or advertiser. |
| **SCORING ONLY** | Synthetic ground truth. Used only to measure identity-resolution accuracy. No model or dbt model may read it. |

Types are BigQuery types. All timestamps are UTC. All money is USD.

## How the tables join

| From | To | Key | Notes |
|---|---|---|---|
| `crm_orders.customer_id` | `crm_customers.customer_id` | customer id | Every order has a customer. |
| `crm_orders.ga_transaction_id` | `ga4_events.ecommerce.transaction_id` (event `purchase`) | transaction id | Web orders only, and only 92% carry the id; app orders never match. |
| `segment_identifies.anonymousId` | `ga4_events.user_pseudo_id` | device id | Links a device to `userId`. |
| `segment_identifies.userId`, `segment_tracks.userId` | `crm_customers.customer_id` | customer id | |
| `ad_spend.(channel, source, medium, campaign, date)` | session channel, source, medium, campaign and start date from `ga4_events` | channel rules (below) | Joined after the sessions model exists. |
| `ground_truth_identity_links.customer_id`, `.user_pseudo_id` | `crm_customers`, `ga4_events` | | Scoring only. |

A **session** is `user_pseudo_id` + the `ga_session_id` event parameter (360,129 sessions in the sample).

## raw.ga4_events (REAL)

A full copy of `bigquery-public-data.ga4_obfuscated_sample_ecommerce.events_*` for 2020-11-01 to 2021-01-31 (92 days, 270,154 devices). It is clustered by `event_name`, `user_pseudo_id` and keeps Google's nested schema. The 5 fields the project relies on most are marked **key**.

Points that affect analysis:

- `user_id` is empty for every device. Google's sample has no login data, which is why identity resolution needs the synthetic CRM and Segment events.
- `traffic_source` is **user level** (how the device was first acquired), not session level. Session channels come from the `source`, `medium` and `campaign` event parameters.
- Values are obfuscated: campaign names often appear as `<Other>`, and some values are `(data deleted)`.
- Only about 3 in 4 sessions carry a `source`/`medium`/`campaign` parameter; the rest are "Unassigned" and are never guessed.
- About 57,000 sessions name the store's own domain (`shop.googlemerchandisestore.com`, `googlemerchandisestore.com`) as their source with medium `referral` or `organic`. GA4 starts a new session when a visitor moves between the main site and the shop, so these are **self-referrals**, not marketing. They contain about a third of all purchase sessions, and the channel rules label them `Self Referral` so they are never credited as a channel.
- `gclid` appears on sessions with no source and on organic sessions (about 38,500 and 15,600 sessions), so it does not prove a paid click. The project never uses it to define paid traffic.
- Of 5,692 `purchase` events, 883 have transaction id `(not set)` and 450 have zero revenue. Valid, de-duplicated purchases number about 4,451.

## raw.crm_customers (SYNTHETIC)

One row per customer, created by the generator. Buyers are real GA4 buyers (minus 12% who check out as guests and never become customers); a small share of non-buyers also register.

| Column | Type | Description |
|---|---|---|
| `customer_id` | STRING | Primary key, `C000001` and up. |
| `first_name`, `last_name` | STRING | Fake name (Faker). |
| `email` | STRING | Fake email address. |
| `email_sha256` | STRING | SHA-256 of the lower-case email, as Segment would hash it. |
| `phone` | STRING | Fake phone number in mixed formats. |
| `country` | STRING | Country. Follows the primary device's GA4 country; a fake country is used when GA4 has none. |
| `created_at` | TIMESTAMP | Account creation time. Within the GA4 window for new customers; earlier for the 20% who were customers before it. |
| `marketing_opt_in` | BOOLEAN | Agreed to marketing email (55%). |

|---|---|---|

## raw.ad_spend (SYNTHETIC)

Daily spend for the paid channels in the sample. Clicks come from real GA4 session counts; the cost per click is an assumption (one value per campaign, plus 10% daily noise). It shows the method, not a real advertiser's results.

| Column | Type | Description |
|---|---|---|
| `date` | DATE | Day. Always inside 2020-11-01 to 2021-01-31. |
| `channel` | STRING | Channel group: `Paid Search`, `Display`, `Paid Social`, `Affiliate` or `Email`. |
| `source` | STRING | Traffic source as seen in GA4, for example `google`. |
| `medium` | STRING | Traffic medium, for example `cpc`. |
| `campaign` | STRING | Campaign name as seen in GA4 (often the obfuscated `<Other>`). |
| `impressions` | INT64 | Ad impressions, derived from an assumed click-through rate. |
| `clicks` | INT64 | Ad clicks: 1.00 to 1.15 times the real session count. |
| `spend_usd` | FLOAT64 | Spend: clicks times an assumed cost per click. |

### Channel rules

Shared by the generator and the dbt sessions model. Applied to a session's `source` and `medium`: no source and no medium gives **Unassigned**; a source on the store's own domain (`googlemerchandisestore.com`, including `shop.`) gives **Self Referral**; `cpc`/`ppc`/`paid` on a search engine gives **Paid Search**; display or banner mediums give **Display**; paid mediums on social sites give **Paid Social**; organic mediums on search engines give **Organic Search**; `email` gives **Email**; `affiliate` gives **Affiliate**; social referrals give **Organic Social**; other referrals give **Referral**; `(direct)` or `(none)` gives **Direct**; anything else gives **Other**. The code is `src/synthetic/channels.py`.

## Identity tables (dataset `identity`)

Written by `src/identity/run.py` from the rules in [identity_resolution.md](identity_resolution.md). Derived from the raw tables, so they are neither REAL nor SYNTHETIC source data; they are a model output.

### identity.identity_links

One row per GA4 device that could be linked to a customer. A device appears at most once.

| Column | Type | Description |
|---|---|---|
| `user_pseudo_id` | STRING | The GA4 device. Primary key. |
| `customer_id` | STRING | The customer the device was linked to. |
| `link_rule` | STRING | Strongest rule that supports the link: `identify_verified`, `order_match`, `identify_unverified` or `email_hash`. |
| `evidence_rules` | STRING | All rules that support the link, strongest first, comma separated. |
| `confidence` | STRING | `high` (`identify_verified` or `order_match`) or `medium`. |
| `evidence_count` | INT64 | Number of evidence rows behind the link. |
| `first_evidence_ts` | TIMESTAMP | Time of the earliest evidence. |
| `had_conflict` | BOOLEAN | Another customer also claimed this device and lost. |

### identity.identity_rejected

Evidence that was not used, so every decision can be audited.

| Column | Type | Description |
|---|---|---|
| `source` | STRING | `identify`, `order` or `resolution`. |
| `user_pseudo_id` | STRING | Device concerned, if known. |
| `customer_id` | STRING | Customer concerned, if known. |
| `reason` | STRING | `hash_conflict`, `unknown_customer`, `no_device_id`, `transaction_not_in_ga4`, `duplicate_transaction_later_device` or `lost_conflict`. |
| `detail` | STRING | Plain-text explanation. |

## dbt layers

### Staging (dataset `staging`)

Cleaned copies of the raw tables, one model per table. Column names and descriptions are in `dbt/models/staging/_staging.yml` (run `dbt docs generate` to browse them). Main changes from raw:

| Model | Grain | What changes from the raw table |
|---|---|---|
| `staging.stg_ga4__events` | one GA4 event | `event_params` flattened into columns: `ga_session_id`, `ga_session_number`, `page_location`, `page_referrer`, `session_source`, `session_medium`, `session_campaign`, `session_term`, `has_gclid`, `engagement_time_msec`, `is_engaged_session`. Purchase fields lifted out of `ecommerce`. Adds `session_key` (`user_pseudo_id` + `.` + `ga_session_id`). The user-level source is renamed `first_touch_*` so it is not mistaken for the session's source. A table, clustered by `event_name`, `user_pseudo_id`. |
| `staging.stg_ga4__purchases` | one valid purchase | Only real transaction ids, revenue above zero, earliest event per transaction. Same rule as the extract the CRM orders were built from. |
| `staging.stg_crm__customers` | one customer | Adds `full_name`, `created_date`; email lower-cased. |
| `staging.stg_crm__orders` | one order | Adds `order_date`, `is_refunded`, `net_revenue_usd` (order value minus refund). |
| `staging.stg_ad_spend` | one paid campaign per day | Empty `source`, `medium` or `campaign` become `(not set)` (13 of 300 rows have no campaign, because those GA4 sessions carried none). Adds `ad_spend_id`, `campaign_key`, `cost_per_click`, `click_through_rate`. |
| `staging.stg_segment__identifies` | one identify event | `traits.*` flattened; `anonymousId` renamed `user_pseudo_id`, `userId` renamed `customer_id`. |
| `staging.stg_segment__tracks` | one track event | `properties.*` flattened; `userId` renamed `customer_id`; `event` renamed `event_name`. |
| `staging.stg_identity__links` | one linked device | Copy of `identity.identity_links`. |

`raw.ground_truth_identity_links` has no staging model: it is for scoring only.

| Column | Meaning |
|---|---|
| `as_of_date` | Day after the latest order in the data. Recency is measured to this day, not to today. |
| `recency_days`, `frequency`, `monetary_usd` | Days since the latest order, number of orders, net revenue in USD. |
| `r_score`, `m_score` | Quintiles, 5 = best (most recent, highest revenue). Equal values share a score. |
| `f_score` | Fixed bands: 1, 2, 3, 4 orders score 1-4, 5 or more score 5. Quintiles cannot split the three quarters of buyers with one order. |
| `rfm_code`, `rfm_total` | The scores as text (`534`) and their sum (3-15). |

| `marts.fct_customer_clv` | one buyer (`customer_id`) | Historical net revenue plus predicted 90-day and 12-month revenue, and 12-month customer lifetime value. Customers without orders are not valued. |

Key columns of `fct_customer_clv` (all columns are described in `dbt/models/marts/_marts.yml`):

| Column | Meaning |
|---|---|
| `historical_net_revenue_usd` | What the customer has actually brought in (order value minus refunds). |
| `expected_repeat_rate_per_day` | Repeat orders per day: the customer's own rate blended with the rate of all buyers (prior of 90 days), because three months of history is too short to trust one customer alone. |
| `expected_aov_usd` | Net value per order, blended the same way (prior of 3 orders). |
| `predicted_revenue_90d_usd` | Expected net revenue over the next 90 days. Within the span the data has observed. |
| `predicted_revenue_12m_usd`, `clv_12m_usd` | The 365-day prediction and history plus that prediction. About four times the observed history and with no churn, so an upper estimate. |

| `marts.fct_customer_segments` | one CRM customer (`customer_id`) | Segment, RFM scores and value for every customer, including those who never ordered. |
